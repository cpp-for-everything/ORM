# Демо 5 — Формата на заявката, наложена от backend-а (при компилация)

**Какво доказва (оси):** (в) един модел над нерелационни системи + (г) backend-
специфично ограничение, наложено при компилация. Redis е ключ-стойност: достъпът е
само по първичен ключ; не-PK предикат изобщо не се компилира — вместо рънтайм грешка
от драйвера. (Аналогично Cassandra изисква предикат по partition key.)

## Файлове
- `backend_shape.cpp` — PK достъп (компилира) + (под `-DDEMO_REJECT`) не-PK предикат.
- `program-output.txt` — PK достъпът се компилира и изпълнява.
- `compiler-output.txt` — уловеният отказ за не-PK предикат.

## Команди (RedisDB е header-only mock — без hiredis)
```
c++ -std=c++23 -I lib/include backend_shape.cpp                # компилира
c++ -std=c++23 -I lib/include -DDEMO_REJECT backend_shape.cpp  # static_assert
```

## Какво да кажете (≈20 s)
> Един модел, но конекторът на Redis налага формата на допустимата заявка: само по
> първичен ключ. Заявка с втори предикат е отказ на компилатора —
> `RedisDB connector supports only primary-key equality WHERE predicates`. Библиотеката
> не се преструва, че Redis е релационна — семантичните разлики стават **статично
> проверими ограничения**, а не рънтайм изненади.
