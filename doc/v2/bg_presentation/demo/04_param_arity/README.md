# Демо 4 — Брой и тип на параметрите спрямо placeholder-ите (при компилация)

**Какво доказва (ос):** (г) валидиране при компилация. `execute(query, params...)`
сверява броя и типовете на аргументите спрямо анонимните placeholder-и в заявката.
*(Добавена след предаването на тезата — продължаващо развитие.)*

**Архитектурна находка (за Q&A):** проверката е за **анонимни** placeholder-и (1:1
позиционно при всеки конектор). Аритетът при **индексирани** placeholder-и (`ph<T,_N>`)
зависи от конектора (PostgreSQL преизползва `$1`; MySQL дублира всяко `?`), затова
там е отговорност на **договора на конектора**, не на общото IR.

## Файлове
- `param_arity.cpp` — заявка с 2 анонимни placeholder-а; коректно и (под флаг) грешно извикване.
- `program-output.txt` — коректните 2 аргумента компилират и се изпълняват.
- `compiler-output.txt` — уловеният отказ за подаден 1 аргумент вместо 2.

## Команди
```
c++ -std=c++23 -I lib/include param_arity.cpp                # компилира
c++ -std=c++23 -I lib/include -DDEMO_REJECT param_arity.cpp  # static_assert (2 == 1)
```

## Какво да кажете (≈15 s)
> Заявката има два анонимни placeholder-а. `execute(q, 7)` подава само един →
> компилаторът отказва: `wrong number of runtime parameters` (изразът дава `2 == 1`).
> Грешка, която в традиционните библиотеки гръмва при bind по време на изпълнение.
