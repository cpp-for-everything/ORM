# Демо 1 — Капабилити gating: MySQL приема, документен отказва

**Какво доказва (оси на уникалност):** (а) `constexpr` IR · (в) един модел над
релационни и нерелационни системи · (г) trait-договор за способности с отказ **при
компилация**. Това е флагманската демонстрация на уникалната комбинация.

## Файлове
- `capability_gating.cpp` — една SELECT…JOIN заявка, два конектора.
- `program-output.txt` — изходът на **приетия** случай (MySQL, релационен).
- `compiler-output.txt` — **уловеният отказ на компилатора** за MongoDB (JOIN).

## Команди (без драйвери, без Docker — само заглавни файлове + Boost.PFR)
```
# ПРИЕМА (релационен): компилира и се изпълнява
c++ -std=c++23 -I lib/include capability_gating.cpp -o pass && ./pass

# ОТКАЗВА (документен): static_assert при компилация
c++ -std=c++23 -I lib/include -DDEMO_REJECT capability_gating.cpp
```

## Какво да кажете (≈25 s)
> Това е **един** C++ модел и **една** заявка с `.join(...)`. Срещу MySQL
> се компилира. Насочвам я към MongoDB — конекторът не декларира
> `supports_joins`, защото документната семантика няма SQL JOIN върху външен ключ —
> и **компилаторът отказва** с четимо съобщение. Никой друг C++ ORM не отказва
> неподдържана операция за конкретно хранилище **при компилация** върху общ модел.

> Уловеният ред: `orm::db: this connector does not support JOIN operations…`
